编写通用的内联形参名补全的 InlayHint for CSS

参考 clangd 对于 c/cpp 的形参显示

职责: 参考现有实现，抽象出可复用的 InlayHint 设计思路
依赖: clangd 的协议路由、结果适配和 hint 生成链路
输入: 现有实现的调用链、协议入口和 hint 相关数据结构
输出: 一套适合 CSS hinter 的分层设计理解与实现边界

AST 是 Abstract Syntax Tree，中文通常叫抽象语法树。

1. 职责: 接收 LSP 请求，并把请求路由到具体处理函数
	依赖: LSP 消息分发与方法注册机制
	输入: 客户端发来的 inlay hint 请求
	输出: 被转交给具体 handler 的请求
2. 职责: 进入 onClangdInlayHints 和 onInlayHint 两个函数
	依赖: 上层路由结果、InlayHintsParams、回调接口
	输入: 已经被路由到对应 handler 的请求参数
	输出: 进入协议适配或标准入口的处理流程
3. 职责: 分析 onClangdInlayHints 的协议适配逻辑
	依赖: 统一的 InlayHint 内部结果、JSON 序列化和扩展协议格式
	输入: 从底层 hint 生成链路返回的 InlayHint 列表
	输出: 适配后的 clangd 扩展版 InlayHint 响应
4. 职责: 分析 onInlayHint 的标准入口转发逻辑
	依赖: 标准 InlayHint 请求参数、底层 hint 生成接口
	输入: 客户端发来的标准 textDocument/inlayHint 请求
	输出: 转交给 Server->inlayHints 的请求调用
5. 两个适配器同样得到的是Server->inlayHints的结果
6. 职责: 理解 ClangdServer::inlayHints 这一层服务封装
	依赖: WorkScheduler、InputsAndAST、clangd::inlayHints
	输入: 文件路径、可选限制范围、回调
	输出: 先获得 AST，再调用核心 hint 生成函数并回传结果

补充理解:
- onInlayHint 和 onClangdInlayHints 都不直接生成 hint，它们都依赖同一个 ClangdServer::inlayHints。
- ClangdServer::inlayHints 也不是核心算法，它只是把“拿 AST + 调度执行 + 调用核心函数”包装起来。
- 真正的核心仍然是 clangd::inlayHints(InpAST->AST, ...)。
